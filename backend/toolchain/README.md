# Tare toolchain

Tare compiles an unchanged Anchor workspace twice, optimizes the linked Tare ELF, and executes both artifacts in native LiteSVM. This workspace contains the `tare` CLI, the replacement `anchor-lang` implementation and macros, replacement `anchor-spl`, `tare-opt`, and `tare-prove`. [The measured matrix](../bench/compat.json) records exercised behavior; an implemented API is not a claim of complete Anchor conformance. [The full program report](../bench/round-six.md) and [unmeasured-input audit](../bench/gaps/unmeasured.json) distinguish measured coverage, stock failures, replacement limitations and missing corpus fixtures.

## Run

```powershell
cargo build --manifest-path toolchain/Cargo.toml -p tare
$env:TARE_BIN = (Resolve-Path toolchain/target/debug/tare.exe).Path
node bench/run.mjs basic-0 basic-1 basic-4
```

Inside a program workspace:

```sh
tare build --host
tare weigh --host
tare prove --host
```

Each accepts `--manifest-path path/to/program/Cargo.toml` and `--features feature1,feature2`. Build and replay use the same selected Cargo features, which are recorded with the corpus. Select a program manifest in a multi-program workspace. Without `--host`, the CLI starts `TARE_IMAGE` (default `tare-toolchain:<CLI version>`) and invokes the same code in the container. Publishing and selecting an immutable image reference belong to the operator. `TARE_HOME` identifies the directory containing the replacement crates; development defaults to this checkout.

Outputs in the user's workspace are `target/deploy/<program>.so` (stock), `target/idl/<program>.json` (stock IDL), `target/tare/<program>.so` (optimized Tare), the pre-optimization `target/tare/<program>.linked.so`, and `target/tare/{build,dependency-graph,optimization,corpus,execution,weigh,proof}.json`. `weigh.json` and `proof.json` follow the published contract schemas, with `optimization` and `recordedCorpus` facts retained and the contract 0.7.1 `replay` payload. Per-program `<program>.build.json`, `.corpus.json`, `.execution.json`, `.weigh.json` and `.proof.json` copies preserve each member of a multi-program workspace; the unprefixed paths retain the latest selected program. Unreached instruction weights are null with zero inputs and contribute nothing to totals.

On this Windows host, Cargo's Schannel network path sometimes fails; `CARGO_NET_OFFLINE=true` uses the populated cache. Some stock IDL builds compile native dev dependencies and require core Perl modules omitted by Git for Windows. `python toolchain/scripts/setup-windows-perl.py` downloads a checksum-pinned portable Strawberry Perl archive into ignored `toolchain/host/`; set `OPENSSL_SRC_PERL` to the printed executable for that invocation. This does not change global Cargo, TLS, Perl, or PATH configuration.

Some production sources contain custom serialization that the stock IDL compiler cannot describe. `--idl` accepts an explicit IDL, validates its schema, announces the input and pins it in the replay bundle. The supplied file's source verification is a separate corpus-preparation step. It is never chosen automatically. The Squads verifier checks the repository's SDK IDL against instruction arguments, ordered account fields, types and errors at the pinned source commit; its provenance is retained beside the IDL. This path does not claim that the stock compiler generated those bytes.

## Command output and container paths

The default output contains Tare's build summary, instruction table or verification result. `--verbose` prints underlying tool output and the exact `docker run` invocation; a failing step always prints its captured diagnostics. One tested lexical path mapper converts host paths into POSIX container paths, including Windows drive letters, nested manifests and a source root above the working folder. Container commands never use the host's path joining rules.

`check` fetches the recorded source, builds it with the selected toolchain and Cargo features, verifies both artifact hashes and replays the pinned corpus. Its final summary contains the record, commit, both hashes, number of rerun transactions, and `matches` or the first difference.

The local rehearsal switch `TARE_REHEARSAL_DEFECT=dispatch-log` deliberately adds one log for the exact instruction bytes `TAREBAD!`. It is printed loudly, recorded in build metadata, and forbidden for attestation. `flag` first verifies an ordinary record and only then builds the requested defect and checks the supplied input. [Rehearsal commands and input](../bench/rehearsal/README.md) retain the artificial origin explicitly.

## Reproducible artifacts

Both compilations use the same path-remapping compiler wrapper. It preserves Cargo's optimization/profile flags and replaces only the crate-disambiguation metadata that embeds absolute dependency locations. The stable identity includes the package name/version, normalized source location, enabled cfgs, target and crate kind. Rustc accumulates repeated metadata options, so the wrapper removes Cargo's original value before supplying the stable one. Host macro crates receive the same remapping policy as SBF crates. Source, Cargo home, Rustup home and generated adapter paths map to fixed prefixes.

The actual compiler refuses an Anchor framework crate outside the verified adapter root during a Tare build. The framework allowlist excludes unrelated user packages whose names happen to start with `anchor-`. `cargo-build-sbf` runs directly; its preliminary `cargo metadata` receives the same patch and locked graph through the supported Cargo executable hook. A post-build graph/lock check rejects substitutions that changed during compilation. Generated adapter directories include a resolved dependency-graph digest, so one program's Solana dependency selection cannot rewrite another program's adapter.

[Two-folder and fresh-cache evidence](../bench/repro/README.md) records byte-identical stock and Tare artifacts, then differential execution. Old records attest the old artifact hashes: reproducibility changes do not silently redefine an already published hash.

## Dependency substitution and versions

The admitted version lines are pinned at 0.31.1, 0.32.1, 0.32.3, and 1.2.2. Other language versions and mixed-version copies of one Anchor package in a single graph are refused by name. Their repository commits and individual program manifests are in [the corpus manifest](../bench/manifest.json). The adapter generator reads the actual stock package graph and presents the common Tare implementation as packages named and versioned exactly like the selected Anchor packages. It expands workspace-inherited dependency declarations in its own generated manifests.

Cargo receives a command-line configuration file containing `[patch.crates-io]`, `[patch."<git URL>"]`, or `[patch."file:///absolute/original/package/path"]`, according to the dependency source. The file URL patch handles Anchor's own path dependencies through Cargo's stable source-patch mechanism. It does not use the restricted `paths` override or depend on its dependency-graph warning. Internal Anchor dependencies in an adapter point to the matching Tare adapters. Before compiling, a second `cargo metadata` query verifies that every Anchor framework package in the resolved graph points to an admitted Tare adapter; any stock framework package fails the build. The resolved graph is saved with the artifact. The isolated [source-patch checks](../bench/history/round-two/transcripts/language/cargo-source-patches.json) exercise registry and reconstructed local Git sources: all 14 framework packages in each graph resolve to Tare. The full repository Git attempt retains its separate host Schannel/submodule-fetch failure transcript.

Only Tare's sources and adapter manifests are generated. The user's source and manifests are compiled in place and are never copied, patched, or rewritten. Cargo resolves the stock graph first; its resolved lock is reinstated for the stock compile after substitution, and the original Cargo.lock bytes (or original absence) are restored when the build exits. Both resolved lockfiles and their hashes are retained under `target/tare/<program>.*.Cargo.lock` and `<program>.dependency-locks.json` for the build audit. Stock and Tare use the same platform-tools, `--arch v0`, profile, and workspace settings, with separate caches for each Anchor version and for stock, Tare, and IDL builds. This prevents same-named artifacts from concurrent cohorts overwriting one another. A per-version pipeline lock also covers Cargo compilation through ELF copying. Tare refreshes the selected program artifacts while retaining dependency caches, so same-named packages in different workspaces cannot reuse one another's ELFs. The stock IDL comes from Anchor's own compile-time IDL protocol. Protocol schema/IDL helper packages retain their upstream definitions; on-chain language/runtime generation comes from Tare.

The 1.x adapter bridges the version's Solana/Borsh dependencies and default absence of legacy IDL management. It preserves the single-lifetime Context and applies the stock handler boundary's lifetime narrowing before invoking unchanged handlers. Manual close rejects self-destination with the stock error; exit after ownership transfer compares serialized bytes without writing and reports the stock ownership error when they differ. `#[program(legacy_idl)]` opts into the legacy dispatcher. Anchor 0.x retains its built-in IDL behavior. Version-specific corpus generation exercises the corresponding dispatch surface. Unsupported source constructs stop compilation with a diagnostic, rather than selecting a stock runtime path.

## Entrypoint and dispatch

The SBF entrypoint borrows the loader input buffer. Its initial scan locates instruction data and the program ID and initializes the shared borrow bookkeeping. Multi-instruction dispatch carries a two-word account-input view (base pointer and duplicate flag); it constructs `AccountCursor` only after selecting an instruction. Programs use lazy account-input dispatch, constructing the cursor after an instruction matches. Anchor 1.2 single-instruction programs keep the scan's cursor directly: this preserves the account count in registers and avoids a measured two-instruction reload. Account descriptors materialize on demand. The raw entry path does not build a heap vector of account infos or an `Rc` graph. The raw build exposes its compact compatible account type. A build requiring an actual SDK account boundary uses compact SDK-backed views unless the source observes the wrapper layout. Raw input materializes one shared descriptor and its borrow cells per used account; custom SDK entrypoints reuse their supplied descriptors. Parsing follows the upgradeable-loader ABI: eight-byte duplicate records, non-duplicate headers, original length, the 10,240-byte growth reservation, alignment, and rent epoch. Duplicate accounts resolve to the same backing record.

Borrow state occupies loader-reserved input storage, and shared/exclusive data and lamport borrows remain checked. A compact private account view shares those cells after SDK exposure, so aliases never bypass a borrow held by unchanged handler or CPI code. Compatibility fields expose RefCell-like borrowed views to unchanged source. CPI validates outstanding borrows before invoking the runtime. `Context.remaining_accounts` has the stock slice interface. Wrappers materialize only the remaining descriptors when the handler can observe them or the context escapes; empty and one-account cases stay on the stack, and larger observable lists use a vector. Plain handlers keep the lazy path.

The program macro emits direct discriminator dispatch and per-handler wrappers. Declared-ID checks, stock instruction-name logs, argument deserialization, account extraction, constraints, handler execution, return data, and exit retain their observable order. Ordinary instruction logs use constant byte strings. IDL dispatch is separate from ordinary instruction bodies. When enabled, it implements the stock Create, CreateBuffer, Write, SetBuffer, SetAuthority, Resize, and Close operations; its lifecycle and malformed cases are differential inputs.

## Accounts and CPI

The Accounts derive follows upstream extraction and constraint ordering. Generated validation writes the complete accounts value into caller-provided uninitialized storage only after all checks succeed. SPL initialization closures use the same output-storage pattern for their account result. Until then, ordinary field locals retain their normal cleanup behavior. The public `try_accounts` adapter keeps its compatible return type; generated handlers avoid transferring a large `Result<Accounts, Error>` value. A hidden constant raw-input parameter specializes account extraction while retaining the same public account types and validation checks. Public SDK entrypoints select the descriptor path; the generated loader entry selects the raw-buffer path. It implements typed and unchecked accounts, signers, programs, interfaces, sysvars, account loaders, optional/boxed accounts and composite groups. Constraint generation covers initialization, payer/signature checks, seeds and bumps, ownership, addresses, executable/rent checks, relations, custom predicates, zero, close and reallocation. The 1.x reallocation path checks a nonzero resize with the same payer and destination before later constraints, returning stock InvalidArgument with the account name and compared keys; 0.x retains its own ordering and behavior. Reallocation tracking has no allocation until a reallocation is actually executed. The matrix shows which combinations have completed differential runs.

Eligible fixed primitive layouts use views over account bytes. The generated code verifies Rust field offsets and alignment against Borsh layout and restricts this path to suitable handlers and account aliasing. Other layouts use Tare-owned Borsh snapshots. Mutation, raw exposure and reload mark snapshots dirty; untouched snapshots skip serialization. Initialization writes the same discriminator at exit. `AccountLoader` exposes checked zero-copy borrow guards. No optimization drops an Anchor validation check.

`CpiContext`, generated `cpi::` clients, `declare_program!` IDL bindings, return values, events and event-CPI use the same instruction bytes and account order as stock. The IDL binding generator reads modern and legacy IDLs and emits account/event types, composite CPI clients and decoding helpers. Large generated utilities that exceed the SBF stack limit are rejected. Anchor 1.x CPI returns retain their captured data and program ID; older versions preserve their read-on-get behavior. Direct System initialization and eligible generated 0.x CPI use stack descriptors. SPL wrappers, generated 1.x clients and general CPI paths allocate dynamic descriptors. Account data itself is not copied by this marshalling. Integer rent calculations use an exact fast path where equivalent to the stock floating calculation, preserving the general calculation outside that range.

The SPL replacement contains token, token-2022, token-interface, associated-token, token extension, metadata and memo wrappers plus matching account state adapters. It calls the actual SPL programs loaded by LiteSVM, identically on both sides. Unsupported SPL modules produce explicit errors. This is a second runtime implementation, not wrappers around stock Anchor account validation.

Error codes, messages, account names and compared values remain observable. Ordinary token-account authority, mint and token-program constraints emit the bare stock errors on 0.x and attach the stock account name and compared public keys on 1.x. Common formatting uses stack storage; unusually long messages retain full formatting rather than truncating. Multiple simultaneous faults and error order are part of the corpus. A divergence, including an error-log-only difference, fails the proof.

## Code size and dispatch boundaries

Generated private instruction wrappers return the SVM status word. A shared boundary logs a failed public Anchor `Result` once and lowers it to that word; successful dispatch does not carry a large `Result<(), Error>` through each wrapper. Public handler signatures and CPI interfaces remain Anchor-compatible. Thin interface-account wrappers and non-unit handler bodies expose their implementations to the optimizer with inline hints; individual heavy instruction wrappers retain their existing policy.

The error representation stores static descriptors by reference and compared values losslessly in compact storage. Short text and decimal values fit inline; longer original values retain an allocated representation. This reduces the native Error layout from 264 to 144 bytes without truncating error text or changing Debug output. Initialized opaque storage prevents Rust validity-niche packing from generating extra aggregate moves across result boundaries. Origin values use an explicit tagged enum selected by their constructor, so an unused public-key origin does not pull base58 formatting into a trivial program. Clone, drop and conversion retain ownership of the complete typed payload. Fixed primitive account fields include u128/i128: reads use checked layout with unaligned loads where needed, and changed-field stores preserve the surrounding bytes. General variable-size account snapshots and public SDK account exposure still allocate. SPL wrappers reuse an already constructed SDK instruction with the SDK's checked invocation rather than duplicating its account and seed vectors. Raw framework account initialization retains stack C ABI descriptors.

Normal typed account loads share one out-of-line implementation per wrapper and payload type. The caller supplies output storage, so the successful path avoids transporting a large `Result<Account<T>, Error>` through each context. Optional loaders retain the stock sentinel and missing-account order, and boxed loads allocate only after validation. Account creation has one shared body; direct in-place mutable loads remain specialized.

SDK-backed account wrappers store snapshots without the raw direct-view variant. Their internal account view is an aligned tagged pointer and borrow guards store one active representation. A typed SDK boundary without an account-layout observation selects an internal SDK-only view: every constructor supplies a real SDK object, including raw constructors, which materialize and reuse the cache. Optional sentinel accounts are recognized before materialization. Its internal pointer is untagged and snapshots need no dirty-state fields because exposed SDK accounts always serialize on exit. Programs that type-check with raw accounts retain lazy raw views. Explicit SDK-layout observations retain the general SDK-compatible representation. Layout observations resolve concrete `Self`, local generic payload instantiations and pinned dependency payload types; unrelated integer or stake-state layout queries do not force SDK accounts. Real typed SDK boundaries still fail the raw probe and select the compatible representation.

Fixed SDK initialization CPIs marshal descriptors and the bounded signer seed group on the stack, preserving meta-ordered borrow checks and shared data-length updates. Compact-SDK token transfers use the same C ABI with fixed token metadata and instruction bytes. Larger user-supplied seed group sets use the existing checked dynamic call. Mixed account codecs process fields in declaration order; primitive fields use guarded fixed-width reads and all other fields retain their Borsh implementation.

The final current-stock gate and remaining exceptions are recorded in [round six](../bench/round-six.md). A program over either performance bar remains a measured failure.

## Linked bytecode

`tare-opt` admits SBF v0 through the actual Agave loader/verifier before and after rewriting. It reads section, symbol, dynamic and relocation tables. Entrypoint, direct-call and relocated code pointers form roots; unknown indirect calls conservatively retain their possible targets.

The stage threads branches/call thunks, forwards safe stack loads, skips identities, simplifies constant branches and applies checked arithmetic rewrites. Compaction physically removes unreachable slots, merges eligible identical direct-call functions with normalized relocation targets, rebuilds section/symbol/string tables and headers, and maps every surviving code/data reference into the rebuilt ELF. Non-call v0 pointer relocations are resolved to the fixed bytecode virtual addresses and removed; syscall call relocations remain. Function-pointer identity is preserved by retaining address-taken functions.

The optimization report records input/output hashes and bytes, removed instructions, merged functions, prelinked relocations and an affine old/new PC map. VM tests cover generated register/memory states and edge cases. The saved whole-program controls compare 9,828 transactions: 9,812 retain identical compute, 16 use less compute, and none use more. Whole-program controls run both Tare-to-compacted-Tare and stock-to-compacted-stock through the differential harness. No file-size or CU reduction is claimed without a measured artifact.

## Proof and measurements

`tare-prove` uses LiteSVM 0.18.2 with its Agave 4.3 runtime, built natively on Windows. Each build runs at the same program address against the same initial state, built-ins, SPL programs, sysvars and metering. Workspace sibling programs use the same stock ELF on both sides.

A corpus is an ordered set of transaction sequences with starting accounts. Eligible generated SPL fixtures are created by retained System/SPL/Associated Token transactions before the target calls, including minting reserves and authority handoff. Sequence provenance distinguishes these from direct typed snapshots for program-derived vaults that a client cannot create. The generator uses deterministic signer keys and the stock IDL. Source hints supply initialization, optional/zero account information, composite groups and imported account owners absent from the IDL. Hints traverse actual external modules without rewriting them. PDA seeds, fixed addresses, signer funding and initializer ordering are resolved where implemented; unsupported input forms are explicit errors. Negative variants run without committing their changes, and successful sequence transactions feed later calls.

Every transaction compares account bytes, lamports, ownership, executable/rent metadata, logs, return data and error. Only the runtime's exact `Program <address> consumed N of M compute units` lines are ignored. The full execution report retains transaction outcomes and the first divergence. The public report commits to the corpus hash and records comparison counts.

Instruction weights are medians of observed successful, attributable instruction executions. No successful input means null weights, never an estimate. Totals sum measured instruction medians. Binary rent uses the same VM Rent configuration and ELF size plus the ProgramData header. Hand-written Pinocchio reference programs and per-PC/syscall gap ledgers live in [../bench/pinocchio](../bench/pinocchio) and [../bench/gaps](../bench/gaps); they remain outside benchmark totals.

## Recorded upstream suites

[../bench/record-tests.sh](../bench/record-tests.sh) runs unchanged stock test suites in the lead's isolated Linux environment and records signed transactions, initial and changing external state, executable programs, slots, Clock coverage and validator outcomes. [Recording details and commands](../bench/recording/README.md) describe the capture format. [../bench/run-upstream-tests.sh](../bench/run-upstream-tests.sh) separately runs the suites against Tare. Both are manifest-driven and accept subsets across the three version cohorts.

`tare prove --host --tests-corpus path/to/tests.json` imports recordings. The CLI also discovers `bench/corpus-data/<manifest-id>/tests.json`. Replay retains both builds' state across transactions and applies captured external changes equally. Preflight rejection is simulated without committed fees; landed failures are retained. Compiler equivalence and reproduction of the validator's own outcome are separate measurements. Missing exact Clock coverage or differing validator outcomes are reported, never filtered. Captured and native stock ELF hashes are both retained for cross-host provenance.

Recorded instruction samples are merged into medians only when attributable to one target instruction; every recorded transaction remains a proof input. `bench/run.mjs` imports upstream suite counts only when source commit and Tare ELF hash match the current build. No upstream validator test count is inferred from native replay.

## Sources and boundaries

The implementation is based on the pinned Anchor source trees' account types, program/account/constraint code generation, error and IDL code; Pinocchio's lazy entrypoint and borrowed account views; and Agave/solana-sbpf serialization, loader, verifier, syscall and post-execution checks. [Cargo's override reference](https://doc.rust-lang.org/cargo/reference/overriding-dependencies.html) defines the source patches. [The corpus manifest](../bench/manifest.json) supplies exact release commits.

The loader retains responsibility for writable-account enforcement, ownership, lamport conservation, data growth and transaction rollback. Differential results are evidence for the recorded corpus, not a universal equivalence proof. The registry and chain-facing commands are implemented. The lead has verified build, weighing, proof, attestation, cross-folder check and positive/negative flag flows in host and Windows-to-image modes against a validator and the report API. Contract 0.7.1 accepts the pinned replay manifest. No Docker, WSL or validator runs on this Windows host. Linux image and validator validation remain explicit lead commands.

## Assumptions

Each manifest entry selects the default feature set of its pinned program manifest. Explicit environment bindings come from the upstream fixture scripts; the env-id program uses the literal from its own `test.sh`. The generated corpus chooses deterministic client accounts and values, records successful sample counts, and leaves unreached instructions unmeasured. Medians use the upper observed middle sample, so every reported CU value is an actual meter observation. No container or validator result is inferred from a native run.

## Attest, check and flag

`--url`/`TARE_RPC_URL`, `--keypair`/`TARE_KEYPAIR`, `--registry-program`/`TARE_REGISTRY_PROGRAM_ID`, and `--api-url`/`TARE_API_URL` configure the chain and report API. The registry defaults to the mainnet program `7viqDjx5k8ffnfnZiBv9dMhxzVhcGSYLMb5bKdDP1XtP` and the API to `https://api.tare.cx`; `--url` has no default. The CLI never reads or writes global Solana configuration.

`attest` requires a matching proof, unchanged current build hashes, and a clean git source tree at the recorded origin/commit. It uploads the canonical report, verifies the API's content hash, sends the registry instruction, confirms it, and prints the record and configured page URL. `check` reads the on-chain account and report by hash, fetches the exact commit, rebuilds and replays the pinned corpus, and compares both build hashes and the corpus hash. `flag` follows the same rebuild checks, executes the supplied signed transaction/account snapshot on both builds, and uploads/sends only when it actually diverges.

Host and image builds apply the same source-path and crate-metadata normalization. Two independent native checkout folders and fresh caches produce byte-identical stock and Tare new_idl ELFs; the native chain flow then rebuilds and checks an attestation from another folder. The default image path mounts the source at `/workspace`; Windows Docker execution was verified by the lead in round four. Previously attested pre-normalization hashes retain their original meaning and require a new attestation for the new build.

The `replay` report field contains a gzip/base64 manifest with its SHA-256: relative manifest path, generated seed and exact generated transactions, captured test/mainnet transactions and starting state, and external ELF hashes/bytes. The corpus hash commits to this complete manifest. Source paths are portable; check does not resample RPC state. Contract 0.7.1 accepts the replay field. [contract-additions.md](contract-additions.md) lists wide-integer encoding and the optional benchmark record-cluster field.

`prove --program ADDRESS --samples N` adds a bounded current-state mainnet corpus using `TARE_MAINNET_RPC_URL` or `--url`. The default is three signatures and the maximum is twenty. Legacy, v0 and v1 transaction messages are accepted; failed transactions are compared too. Signatures, signed transactions, current account/Clock/lookup-table snapshots and external program bytes are kept for replay. These current-state executions do not claim to reproduce the historical bank.

The ordinary Anchor [registry workspace](../registry/README.md) owns fees and records. The [single Linux entry point](../bench/README.md#one-linux-entry-point) builds tools separately from pristine corpus checkouts, records stock suites, tests Tare suites, and retains their real transcripts. Native RPC rehearsals use real LiteSVM execution and a local report store; they are distinct from the lead's validator runs.

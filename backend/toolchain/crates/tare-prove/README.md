# tare-prove

The runner executes complete signed transactions in two native LiteSVM 0.18.2 instances. Both instances start from the same cloned environment and account set, use the upgradeable loader, and differ only in the loaded program ELF. LiteSVM supplies mainnet feature defaults, builtins, sysvars, SPL programs, transaction signature verification, the blockhash, and compute metering.

A corpus is a serialized list of sequences. A sequence declares its starting accounts, deterministic test signer entropy, fee payer, and ordered transactions. Committing cases carry state into the next transaction. Speculative cases run on cloned pre-state and leave the sequence unchanged. This lets malformed init inputs run before a successful init without contaminating it. The same representation accepts later test-suite and mainnet corpora.

The generator reads instruction data, account flags, fixed addresses, PDA seeds, and type definitions from the stock IDL. Syntax-only source hints supply the two facts absent from that IDL: which constraints initialize accounts, and which account data type a field wraps. It orders initialization before later calls, reuses generated identities, funds signers, derives PDAs, serializes Borsh arguments, and varies argument values over four deterministic sequences. It currently understands primitive arguments, defined structs/enums, arrays, empty vectors and None options, constant/account-key/argument PDA seeds, and fixed account addresses. An unresolved account-data seed or type stops generation with a named error.

Each successful transaction contributes its SVM compute units to the instruction when the transaction contains exactly one instruction. The report uses the upper median of the observed integer counts. No successful input means null weights, never zero or a prediction. Multi-instruction imported transactions still participate in equivalence; they do not have their aggregate compute attributed to a single instruction.

After every submitted transaction the runner compares account data, lamports, owner, executable flag, rent epoch, complete logs, return data including its program id, and transaction error. It ignores only a complete runtime log line matching `Program <valid address> consumed <integer> of <integer> compute units`. A similarly worded user log is retained. A divergent input contains its signed transaction, pre-state accounts and every observed difference. The runner continues collecting outcomes while retaining the first divergence, and the caller must fail the proof when that field is present.

The generator includes missing account lists, missing signatures, read-only metas, unknown instruction discriminators, short instruction arguments, malformed account data, wrong owners and wrong PDA accounts. Combined malformed data and missing signer cases exercise first-error ordering. The corpus also covers the built-in IDL dispatch tag (malformed encodings and each decoded variant with missing accounts) and the event-CPI stub tag. A complete IDL account lifecycle exercises all seven operations, including system CPI creation, resizing, authority changes, buffer replacement, closing, and account mutations. Its malformed, aliased and undersized inputs compare validation ordering and panic logs. Account metadata differences use `account_metadata`, and divergent input account snapshots include `rentEpoch`. These are explicit extensions to the initial services schema rather than losing a measured difference or omitting part of the replay state.

`program_rent` asks the same LiteSVM environment for the rent of the upgradeable ProgramData account (`ELF length + 45`). It is a local SVM figure, not an RPC quote for a changing network parameter.

The CLI uses `source_hints`, `generate_corpus_for_version`, `run_with_programs`, `run_recorded`, `merge_recorded`, and `program_rent`. The CLI owns artifact paths and report persistence. No validator, Docker, WSL, RPC or network call occurs during proof execution.

## Exact JSON integers

External u64 fields accept an integer token or a nonnegative decimal string. Values through 2^53 - 1 serialize as JSON numbers; larger values serialize as decimal strings, including account lamports/rent epochs, corpus seeds, recorded slots and validator compute units. Replay inputs include rentEpoch as well as lamports. Legacy recorded projections that omit rentEpoch use their rich preAccounts snapshot; an explicitly supplied rentEpoch must match it. Nested account snapshots, divergence details and register traces receive the same canonical representation. Parsing rejects floating-point values, negatives and overflow rather than rounding them. These fields remain u64 inside the native harness.

`cargo run --manifest-path toolchain/Cargo.toml -p tare-prove --example exact_u64_replay -- ELF IDL REPORT.json [REPLAY_INPUT.json]` executes a signed failure transaction over a funded deterministic test payer and an account with rentEpoch=u64::MAX. It roundtrips max lamports/slots/compute values, verifies exact replay, and checks that a deliberate rent-epoch mismatch is retained. The optional input output is a real `TAREBAD!` transaction targeting the supplied IDL's program; it is a local rehearsal fixture, not a mainnet sampled input. The existing `recording_smoke` continues to exercise ordered successful and failing transactions and sample merging.

Recorded transaction metering resolves a sanitized message using the replay SVM's own AccountsDb address loader, with its captured Clock and SlotHashes lookup-table rules. Static keys are followed by loaded writable and readonly keys in the SDK's order. Invalid address-table/message inputs remain differential proof inputs with no attributed instruction sample; they are not filtered. A v0 program ID must remain in the static key list under the installed Agave rules. A transaction with exactly one top-level target instruction can be metered; CPI-only or multi-instruction target cases remain compared but unattributed. The exact-u64 replay example also executes a signed v0 transaction whose readonly application account comes from a real lookup-table snapshot and verifies its measurement.

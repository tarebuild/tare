# Linked SBF compaction

`tare-opt::optimize` validates the input with LiteSVM's Agave loader, applies the instruction rewrites, compacts the linked ELF, and validates the result with the same loader. The public `Optimization { bytes, stats }` API remains unchanged. Only SBF v0 is admitted; the stage preserves the ELF version and does not select a different build profile.

The compactor removes unreachable instruction slots and merges direct-call function bodies whose instructions and relocation meanings match. Function fingerprints include resolved data addresses, internal call targets, and syscall names: equal opcode bytes with different literal or call targets are not sufficient. For indirect calls, a finite value-flow analysis starts at the ELF entrypoint, tracks immutable relocation-backed vtable values, register copies and arithmetic, stack spills, direct-call parameters, returns, and caller-saved registers. It propagates both conditional successors. Partial stores and unknown writes invalidate tracked stack cells. Recursion and analysis bounds are explicit unresolved reasons. Unreferenced dynamic exports are not runtime entrypoints and can be removed when the complete reachable call graph is proven. A reachable unresolved callx keeps every text instruction and disables function merging because SBF v0 allows arbitrary instruction targets, including addresses inside a function. Numeric immediates that merely coincide with an image address remain unchanged.

The resulting text is physically shorter. Branch and call displacements, entrypoint, function symbols and sizes, relative data/code pointers, symbolic relocation addends, relocation sites, dynamic-table addresses and sizes, section offsets/addresses, and program segments are rebuilt. Relocations attached to removed instruction sites are removed. Live non-call `R_BPF_64_RELATIVE` and `R_BPF_64_64` relocations are resolved into absolute addresses using the fixed v0 `MM_BYTECODE_START` base, then their records are removed. The loader leaves these already-resolved pointer words untouched. Call relocations stay present for syscall lookup; an empty remaining relocation table clears `DT_REL` as required by the parser. Removed local function symbols are cleared while symbol indices remain stable. Nonallocated `.debug*` and `.comment` payloads are dropped; deployed test images already lack these payloads. Nonempty `.eh_frame`, RELA relocations, uninitialized segments, and unimplemented dynamic tags are explicit errors.

`Stats.pc_map` contains affine ranges `[old_instruction_start, new_instruction_start, instruction_count]`. It includes aliases for merged bodies. `text_slots_removed` counts physical eight-byte slots, including both slots of a removed LDDW. `text_bytes_removed`, `relocations_removed`, `relocations_prelinked`, `identical_functions_merged`, and the actual input/output file sizes distinguish code removal from metadata and padding changes. Earlier instruction-rewrite counters describe the pass before compaction.

Tests execute before/after code in the production SBF interpreter over six boundary values and 48 deterministic generated states. They compare program registers and every byte of input, heap, and stack memory, plus execution errors and instruction counts. The internal VM instruction index is checked against `pc_map` rather than compared numerically after layout changes. Full-ELF cases exercise direct and indirect calls, symbolic and relative relocations, function pointers, unequal literal targets, dead symbols, and debug removal. The product's transaction differential harness remains the check of account state, logs, return data, and errors for complete programs.

Frozen measurements and hashes are in `backend/bench/gaps/round-three/opt/frozen/results.json`; the later prelinked results and direct stock/Tare controls are in `backend/bench/gaps/round-three/opt/prelinked/`. The prelink controls compare 9,828 transactions, including stock basic-0 and stock misc, with identical behavior: 9,812 transactions have equal CU, 16 use fewer CU, and none use more. They retain remaining size regressions; the compactor does not turn an oversized language implementation into a claimed size win.

The JSON stats include `indirectCallSites` with original PCs, recovered target PCs, and unresolved reasons, plus `unresolvedIndirectCalls` and `retainedForIndirectCalls`. These are analysis facts, not promises that every indirect call has been resolved. The current complex SDK error-formatting paths still produce unresolved sites. Round-five controls under `bench/history/round-five/optimizer/` record those limits alongside before/after bytes and unchanged instruction medians.

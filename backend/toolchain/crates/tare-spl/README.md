# Tare SPL adapters

This crate supplies the `anchor-spl` dependency replacements for Anchor 0.31.1, 0.32.3, and 1.2.2. Its public CPI structs, function signatures, instruction builders, account ordering, and signer-seed behavior follow the pinned Anchor source at commit `47284f8f0b9844c6b83234aa90f556bad00e12ed`. The 0.31 and 0.32 public wrappers share `src/`; `versions/v1/` follows the 1.2.2 interface crates and selected Solana cohort. The compatibility glue is derived under Apache-2.0; `NOTICE` records its provenance. No stock Anchor runtime is linked.

The structs contain Tare `AccountInfo` views. CPI builds the same SPL instruction and passes the instruction's own program ID, metas, exact account-info list, data, and seeds to Tare's C ABI invocation. It does not substitute `CpiContext.program` for an instruction's program ID: classic Token and Associated Token instruction builders use fixed program IDs, while Token-2022 builders take the context program ID. Wrappers that use unsigned invocation in stock Anchor keep unsigned invocation here. Metadata wrappers include remaining accounts exactly as the stock context does.

`token::Mint` and `token::TokenAccount` deserialize using SPL Token's `Pack::unpack`. The interface account types deserialize the base state through Token-2022's `StateWithExtensions::unpack`, accept the same two owners, and expose the same state fields. Serialization is an explicit no-op, as in stock Anchor: changes to token state happen through CPI, not by writing a copied wrapper. Metadata account wrappers keep the stock safe-deserialization and key checks. Errors from Borsh metadata reads pass through `ProgramError` before the Tare error wrapper.

Modules present: `token`, `token_2022`, `token_interface`, `associated_token`, `metadata`, `memo`, `mint`, and all public Token-2022 extension wrappers present in Anchor 0.31.1. The confidential-transfer source modules have no public wrappers in that release. `governance` and `stake` features stop compilation with named diagnostics. IDL generation uses the stock dependency graph; the toolchain does not regenerate the IDL from these adapters.

Verification runs against complete programs using the differential SVM corpus. Native compilation with default features plus `metadata,memo` checks the public adapters together. Native compilation alone is not an equivalence result; measured results and any divergence are recorded by the toolchain in the program proof and bench reports.

The version adapter retains each workspace's SPL dependency declarations and selects the corresponding source set. It preserves 1.2.2's `CpiContext.program_id` and Pubkey constructors, while 0.31/0.32 contexts carry a program account. Default-token modules plus `metadata,memo` compile against both the 0.31.1 and 1.2.2 dependency sets. The exercised 1.2.2 path uses its default `solana-v3` cohort; `solana-v4` is not yet verified. Full program proofs remain the evidence for behavior, rather than compilation alone.

Assumptions: the adapter selects the dependency versions matching the workspace's supported Anchor release. The SPL programs loaded in the SVM remain the actual SPL implementations. Panic-source paths for the stock infallible `get_mint_extension_data` borrow are subject to the same source-path mapping as other dependency panic locations and require full-program differential coverage.
